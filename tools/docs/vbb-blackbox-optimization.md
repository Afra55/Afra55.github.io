## 硬约束（不可破 · 2026-10-02）

> 改策略前先改这里；单测：`node tools/vbb-blackbox-fps.test.js`（已进 CI）。

1. **时间轴优先于标称高帧 / 宽度**：成片 fps 必须落在片源「整除档」  
   - ≈24fps 电影 → 只许 **24 / 12**  
   - ≈25fps 屏录 → 只许 **25 / 12.5**（禁止 20、15）  
   - ≈30fps → **30 / 15 / 12**  
   - 其它 → **20 / 15 / 12**
2. **≤24s 进预算后**：禁止「可读宽优先」再把流畅档降到更低档换宽度  
3. **拼接产品形态**：始终 **多段 → 一条中间 MP4 → 一条 GIF**（不分段各出 GIF）  
4. **中间片**：保留片源帧率；抽到黑盒档只在转 GIF 时做一次  
5. **体积硬闸**：默认 ≤10MB，超限不交付  
6. **宽度策略（2026-10-02）**：420 清晰工作点；380 硬底；超限先守 420 再降质；余量先抬画质再加宽（禁「更宽更糊」）
7. **调色板 / 摄影色**：勿过早 `gifsicle --colors 128`；**禁止**「电影 lossy 腾预算再加宽」（见 `e95ca7e`）
8. **抬质吃满**：略超限可轻压进预算；整档装不下试中间 gq 半档；阶梯含 **q18**（见 `9a98dc6`）
9. **满画质禁 lossy 留底**：gq≈92（及已进预算成片）**只许 -O3**；禁止 `compressExistingGifToBlackbox` 硬压 / movie lossy / 过早 `--colors` 留底。干净次档 > 脏满档贴 10MB
10. **单任务并行**：UI 一次只跑一个用户任务；桌面原生 gifski 下同一任务内试档最多 2 路；手机 / wasm 回退保持 1 路

主目标排序：**时间轴干净 > 标称高帧 > 420 清晰（画质） > 加宽 > 少试编**。

## 产品目标（验收口径）

在 **≤ 可配置上限（默认 10MB）** 下，整段黑盒 GIF 尽量：

1. **流畅**：片源整除档 + 均匀 delay（避免可变 delay / 不规则抽帧顿挫）
2. **清晰**：默认守 **420 清晰工作点**；有余量先抬画质到满档，再加宽/提帧；不得破坏硬约束 1–2
3. **不超限**：硬闸 `enforceBlackboxMaxBytes`，超限不交付
4. **可预期**：真实试编码决策（不用「拍脑袋估算」定档）

建议「到极致」验收：

| 场景 | 期望 |
|------|------|
| 短片 ≤10s（25 源） | 优先 **25fps** 进预算；满画质优先于盲目加宽 |
| 中片 / 拼片 ~16–24s（25 源） | **12.5fps** 整除档；优先 **420 + 更高画质**，勿「更宽但更糊」 |
| 难压长片 | ≤上限内优先保 420 清晰与画质，帧率走低档整除；380 仅硬底 |

## 当前策略摘要（代码真相）

- **帧率阶梯（按片源）**：≈24 电影 → `24,12`；≈25 屏录 → `25,12.5`；≈30 → `30,15,12`；其它 → `20,15,12`  
  时长主档：`≤16s` 高档 · `≤24s` 中档 · `>24s` 低档
- **宽度两档**：**420 = 清晰工作点**（`BASE_W` / `COMFORT_W`）；**380 = 硬底线**（`MIN_ACCEPT_W`）
- **起点**：宽 420、gifski 近无损（质量档 1）
- **进预算顺序（超限让渡）**：满画质@420 → 同宽降画质阶梯（`1→8→15→18→22→30`）→ 才允许 380（满画质二分回爬再降质）→ 更低整除档 →（必要时）gifsicle 硬压  
  - 硬压默认 **摄影友好**：勿早 `--colors`；减色尽量晚
- **有余量顺序**：先抬画质到满档（同宽）→ 满档后才加宽 → 提帧（只提到整除高档）→ 再加宽 → O3 → 硬闸  
  （画质未满时跳过加宽，禁止「442 宽 · q65」这类宽而不清）
- **抬质细则**：
  1. 抬到更高 ladder 档时，原始略超 10MB → `blackboxAcceptBoostIfFits` 试压进预算（不再硬拒）
  2. **满画质（gq≈92）只许 -O3**（抬质 / 近超限保 420 / 硬闸第一步 / 换宽轻压 / `compressAt` 均同）；非满档最多 O3 + 一轮很轻 soft（lossy≈28）；**禁止**硬压 movie lossy 留底
  3. 整档仍装不下 → 试 **中间 gq 半档**（如 65→~70）
  4. 阶梯含 **q18**（`V2G_BLACKBOX_QUALITY_LADDER = [1,8,15,18,22,30]`）
  5. 硬压 `--colors` 延到 **r8/r9**（192/128）；满档 `qualityBest` 时 `compressExistingGifToBlackbox` 强制 `mode=o3`
- **调色板禁令（`e95ca7e`）**：**取消** finish/O3 后「电影 lossy 腾预算再加宽」；lossy 会合并调色板，加宽失败时留下泥色成片（601）
- **拼接**：多段 → 一条中间 MP4 → 一条 GIF；中间片保留片源帧率
- **规则单测**：`tools/lib/vbb-blackbox-fps.js` · `tools/vbb-blackbox-fps.test.js`

关键常量（名称以源码为准）：`V2G_BLACKBOX_MAX_BYTES`、`V2G_BLACKBOX_HIGH_PRIMARY_SPAN_SEC`、`V2G_BLACKBOX_MID_SPAN_SEC`、`V2G_BLACKBOX_BASE_W`、`V2G_BLACKBOX_COMFORT_W`、`V2G_BLACKBOX_MIN_ACCEPT_W`、`V2G_ENCODE_HARD_W`、`V2G_BLACKBOX_QUALITY_LADDER`。

## 优化历程（按主题）

### A. 体积上限与硬闸

- 默认黑盒上限从历史档位演进到 **可配置持久化、默认 10MB**（全站 `devtools:blackbox-size`）
- 成片路径统一 **O3 优化 →（可选）再加宽 → `enforceBlackboxMaxBytes`**
- 超限优先「按比例无损重编缩宽/降帧」，尽量晚用 gifsicle `--lossy`（颗粒感）

### B. 帧率与流畅度

- 去掉 10fps 底线；主决策 **20 → 15 → 12**
- 短片曾「先 15 再余量冲 20」，后改为 **≤16s 主试 20**（10MB 下更顺）
- GIF 厘秒时基：改为 **固定均匀 delay**（20→50ms / 15→70ms / 12→80ms），避免累计取整「一顿一顿」
- **≥18fps 禁止静止帧合并**（可变 delay 在动作段易顿挫）；**短片 ≤16s** 即使 15/12 也不合并；更长片 15/12 仍可合并省体积
- 「压缩时长」= `setpts` 倍速缩短有效时长；**不应**再被误标成「更卡」的原因
- **拼接卡顿根因（已修）**：旧逻辑把 25fps 源压成黑盒主档 20 → 中间片与 GIF 都抖；现保留片源帧率

### C. 宽度与吃满预算

- 加宽二分目标贴 **~0.99× 预算**；旧「超一点回退过大 + 探次少」会导致常用不满
- O3 后再加宽，把优化腾出的字节换成清晰度
- **短片欠填**：实测 4.8s@2532 曾只到 **~3.0MB / 630px（约 30%）**，因 finish/O3 加宽卡在 **2× / 1.5×**  
  → 已改为 ≤24s **探满源宽/1280**，提帧后再补一轮加宽（需同片复测确认）

### D. 手机 / 性能 / 内存

- 性能档（自动/拉满/均衡/省电）影响 gifski 帧上限、加宽探次、是否质量上探、批并发
- 手机分块编码防 OOM；桌面默认少分块；**拉满**=少分块、加宽探更多
- **手机始终一次只转一路**（`batchConcurrency=1`），多选也逐个；探宽 ≤2；满档远超预算时跳过中间画质档
- 手机抬质：**最多一档**；≥88% 预算跳过抬质；跳过半档 / 第二轮抬质 / 加宽 / O3 后再抬 / gq100 上探（防 wasm OOM）
- 手机「自动」：未知机型默认拉满；核数 ≥6 抬满（旧 ≥8 / 默认均衡体感偏慢）
- 电脑桌面/拉满多选最多 2 路；手机 wasm **不能**真多线程——单路极致=少试档，不是多核狂编
- **桌面加速（保流畅+清晰）**：选定整除帧率与 420 后，抬质能进预算就连爬；**上一档 O3 进不去即停**（不反复半档/第二轮/O3 后再抬）；同档走 `trialCache`。满档才加宽。
- **校验**：601 桌面 **546s→206s**，仍 20fps·420·画质74·9.75MB；0087 **388s→166s**，仍 30fps·420·画质83·9.76MB。帧率/420 未降，去掉的是进不去的白跑。
- **校验**（`VBB_BENCH_MOBILE=1`，601.mp4 15.8s 1920×1440，强制 wasm）：约 **146s** 出片 · 420·画质70(档18) · 8.24MB · ≤10；日志含 `手机加速：满档…从 q18 起试` / `跳过加宽/第二轮抬质`
- 次要选项折叠；布局改为横排紧凑（避免强制竖排全宽）

### E. 交互与流程

- 整段 / 长视频切片 / 手动打点；多选批次；编辑页复用 trim/crop
- 「拼接后转黑盒」：多段先拼再整段黑盒（后修纯视频高帧中间片）
- 防息屏 / 完成提示音震动 / 自动打包下载 / 分享到相册

## 改策略时的注意点

- **先改 `v2g-suite-src/`，再 build**；不要只热修 `v2g-suite.js`
- 动帧率 / delay / 静止合并后，务必用「动作段录屏」看是否顿挫，不能只看体积
- 动加宽上限后，用「短 + 源很宽 + 画面简单」片验证吃满，用「长 + 高噪/高动作」片验证不超限、不 OOM
- 面板文案保持短；说明写进本文或面板折叠区
- **加宽必须沿用当前画质档**（`encodeKeepQ`）：q65 入选后再用 q92 探宽会全失败白跑
- **画质未满档时跳过加宽**（以 `gifskiQuality` 为准，勿只看 ladder `quality`）：避免「442 宽 · 画质 65」宽而不清
- **抬质改档勿沿用旧 gq**：否则会编出「q1 标签 + gq65」假成功
- **勿过早 `--colors 128`**：摄影/渐变片会泥色；减色只作末档硬压手段
- **勿恢复「电影lossy腾预算」**：省下的字节加宽吃不到，失败却留下崩色成片
- **抬质略超限要试压**：否则易停在 6.5MB·画质65，预算闲置

### 2026-10-03（残留脏像素路径清扫 + 单任务双路试档）

- **现象**：抬质闸门修完后，满档仍可能脏：`fitFps` 近超限「轻压保 420」、硬闸、换宽 1.06、`compressAt(isLast)` 仍走 `compressExistingGifToBlackbox` **movie hard lossy**；标签画质 92。

  3. 原生 gifski **显式 `--threads`**（并行时按 inflight 均分核）；quality≥90 忽略误传 `--lossy-quality`

### 2026-10-03（满画质禁抬质 lossy 颗粒）

- **现象**：`D:\Download` 新成片 617/618/619 标签画质 92，但密麻颗粒点；调色板仍满 256（非 601 泥色）
- **样本**：617 9.80MB · 420×316 · 25fps · 270帧；618 9.47MB · ~14.3fps · 251帧；619 6.85MB · 20fps · 200帧（同源视频当日未同名落盘，近邻 596/597/601.mp4）
- **根因**：`9a98dc6` 的 `blackboxAcceptBoostIfFits` 对满档用硬压前 4 档 movie lossy（≈92–176）硬塞进 10MB；O3 后再叠 lossy 留底 → 抖动噪点

### 2026-10-02（抬质吃满预算 · `9a98dc6` / `v2026.10.02-234525`）

- **现象**：fitFps 在较低档（如 q22）进预算后，抬到更高档原始常 12MB+ 被硬拒；旧电影lossy 又把成片压到 ~6.5MB，抬质从不「高档+轻压」→ 余量闲置、停在画质65
- **改动**：
  1. `blackboxAcceptBoostIfFits`：抬质略超限时硬压前 4 档试压进预算
  2. 整档装不下 → 中间 **gq 半档**（如 65→70）
  3. 阶梯补 **q18**：`[1,8,15,18,22,30]`
  4. **不**恢复过早减色与电影lossy腾预算
- **复测**：留给次日强刷（见上文「明天强刷复测」）；重点看原 6.5MB/画质65 片是否抬质
