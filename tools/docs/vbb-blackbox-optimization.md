## 产品目标（验收口径）

在 **≤ 可配置上限（默认 10MB）** 下，整段黑盒 GIF 尽量：

1. **流畅**：短片优先 20fps；≥18fps 用均匀 delay（避免可变 delay 顿挫）
2. **清晰**：有余量先加宽再提帧；录屏文字可读优先于盲目冲帧
3. **不超限**：硬闸 `enforceBlackboxMaxBytes`，超限不交付
4. **可预期**：真实试编码决策（不用「拍脑袋估算」定档）

建议「到极致」验收：

| 场景 | 期望 |
|------|------|
| 短片 ≤10s | 体积 ≥90% 上限，**或** 已达源宽 |
| 中片 ~10–20s | 体积 ≥95% 上限 |
| 难压长片 | ≤上限内优先保宽 ≥420、画质档尽量浅，再考虑 12fps |

## 当前策略摘要（代码真相）

- **帧率阶梯**：有效时长 `span/speed` → 主档 `≤16s: 20` · `≤24s: 15` · `>24s: 12`；底线 **12**（不再掉 10）
- **起点**：宽 420、gifski 近无损（质量档 1）
- **进预算顺序**：收窄 → 浅降质 → 更低帧 →（必要时）gifsicle
- **有余量顺序**：加宽 → 提帧（短片冲 20）→ 短片再加宽 → 画质上探 → O3 → O3 后再加宽 → 硬闸
- **短片加宽上限**：≤24s 探到 `min(源宽, 1280)`，目标约 **99%** 预算；长片仍约 **2×** 控探测成本
- **拼接后转黑盒**：多段按顺序先合成一条 MP4，再整段黑盒；只拼画面；中间片帧率对齐黑盒主档（20/15/12）；各段「编辑」的裁时长/裁画面会带进拼接

关键常量（名称以源码为准）：`V2G_BLACKBOX_MAX_BYTES`、`V2G_BLACKBOX_HIGH_PRIMARY_SPAN_SEC`、`V2G_BLACKBOX_MID_SPAN_SEC`、`V2G_BLACKBOX_BASE_W`、`V2G_ENCODE_HARD_W`、`V2G_BLACKBOX_QUALITY_LADDER`。

## 优化历程（按主题）

### A. 体积上限与硬闸

- 默认黑盒上限从历史档位演进到 **可配置持久化、默认 10MB**（全站 `devtools:blackbox-size`）
- 成片路径统一 **O3 优化 →（可选）再加宽 → `enforceBlackboxMaxBytes`**
- 超限优先「按比例无损重编缩宽/降帧」，尽量晚用 gifsicle `--lossy`（颗粒感）

### B. 帧率与流畅度

- 去掉 10fps 底线；主决策 **20 → 15 → 12**
- 短片曾「先 15 再余量冲 20」，后改为 **≤16s 主试 20**（10MB 下更顺）
- GIF 厘秒时基：改为 **固定均匀 delay**（20→50ms / 15→70ms / 12→80ms），避免累计取整「一顿一顿」
- **≥18fps 禁止静止帧合并**（可变 delay 在动作段易顿挫）；15/12 仍可合并省体积（观感有张力，见「未闭环」）
- 「压缩时长」= `setpts` 倍速缩短有效时长；**不应**再被误标成「更卡」的原因

### C. 宽度与吃满预算

- 加宽二分目标贴 **~0.99× 预算**；旧「超一点回退过大 + 探次少」会导致常用不满
- O3 后再加宽，把优化腾出的字节换成清晰度
- **短片欠填**：实测 4.8s@2532 曾只到 **~3.0MB / 630px（约 30%）**，因 finish/O3 加宽卡在 **2× / 1.5×**  
  → 已改为 ≤24s **探满源宽/1280**，提帧后再补一轮加宽（需同片复测确认）

### D. 手机 / 性能 / 内存

- 性能档（自动/拉满/均衡/省电）影响 gifski 帧上限、加宽探次、是否质量上探、批并发
- 手机分块编码防 OOM；桌面默认少分块
- 次要选项折叠；布局改为横排紧凑（避免强制竖排全宽）

### E. 交互与流程

- 整段 / 长视频切片 / 手动打点；多选批次；编辑页复用 trim/crop
- 「拼接后转黑盒」：多段先拼再整段黑盒（后修纯视频高帧中间片）
- 防息屏 / 完成提示音震动 / 自动打包下载 / 分享到相册
- 多图 → GIF 模式
- 文案大幅精简，减少干扰

## 改策略时的注意点

- **先改 `v2g-suite-src/`，再 build**；不要只热修 `v2g-suite.js`
- 动帧率 / delay / 静止合并后，务必用「动作段录屏」看是否顿挫，不能只看体积
- 动加宽上限后，用「短 + 源很宽 + 画面简单」片验证吃满，用「长 + 高噪/高动作」片验证不超限、不 OOM
- 面板文案保持短；说明写进本文或面板折叠区
- **加宽必须沿用当前画质档**（`encodeKeepQ`）：q65 入选后再用 q92 探宽会全失败白跑
